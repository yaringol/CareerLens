# משימה 04: יצירת 20-40 קו"ח PDF אותנטיים + ground-truth

> בריפינג לאייג'נט עצמאי. לא תלוי בקוד - אפשר להתחיל מיד.
> כללי הברזל מ-[00-MASTER-PLAN.md](00-MASTER-PLAN.md) מחייבים.

## מטרה

ליצור סט של 20-40 קבצי PDF של קורות חיים שנראים **אמיתיים ואותנטיים לחלוטין** - לא "נוצרו
ע"י תבנית", לא אחידים, לא סטריליים. לסט שימוש כפול:

1. **דמו ובדיקות רנדומליות ביום השיפוט** - שופט יכול לבקש "תעלי קו"ח" והמערכת תתמודד יפה.
2. **ה-test set האמיתי של מודל 2** - הבסיס ל-benchmark במשימה 05, שמספריו ייכנסו לספר
   הפרויקט במקום ה-0.93 הסינתטי. לכן **חובה ground-truth מתויג לכל קובץ**.

## דרישות תוכן

### כיסוי תרחישים (מתוך [01-model2-cv-title-classifier.md](../ds-models/01-model2-cv-title-classifier.md), "שלב 1")

| קטגוריה | כמות מומלצת | מה בודקים |
|---|---|---|
| ברור וחד-משמעי (Backend+Django+Postgres מובהק וכד') | 8-10 | auto-accept בצדק |
| עמום/גבולי (Fullstack מול Frontend מול Backend) | 4-5 | נופל ל-manual בצדק |
| מחליף קריירה (QA שעבר לאוטומציה/פיתוח) | 2-3 | top-3 סביר |
| היברידי (ML Engineer שגם Data Engineer) | 2-3 | top-3 מכיל את שתיהן |
| ג'וניור/סטודנט (ניסיון דל, בעיקר לימודים ופרויקטים) | 2-3 | לא מתבלבל מרעש |
| תפקיד נישתי בתחום הליבה של המודל (SOC Analyst, Embedded, Firmware) | 3-4 | חשוב! 59 הטייטלים נוטים לסייבר/חומרה |
| תפקיד לא נתמך (Game Developer, DBA נדיר) | 1-2 | נופל לטייטל נתמך הגיוני |
| עם "רעש" אמיתי (טבלאות, שתי עמודות, אייקונים) | 2-3 | עמידות חילוץ ה-PDF |
| דו-לשוני / משפטים בעברית בתוך קו"ח באנגלית | 1-2 | התנהגות הוגנת / fallback |

- **עודכן ב-kickoff (2026-07-14, אושר ע"י המשתמש):** הטייטלים המתויגים מגיעים ממרחב
  **59 הכותרות הקנוניות** של `ds/model/taxonomy.py` (`CANONICAL_TITLES`) או `"none"` -
  **לא** מ-38 המחלקות של `label_map.py` (מיושן: המסווג המוגש אומן מחדש על 59+`__other__`,
  אומת בטעינת המודל). ולידציה אוטומטית של כל `true_title` מול `taxonomy.py` היא חובה.
- **סקילז עדכניים ל-2026**: לצד הקלאסיים - להכניס במינון טבעי דברים כמו LLM/RAG/agents
  לתפקידי ML, K8s/Terraform/ArgoCD ל-DevOps, Rust במקומות מתאימים. לא בכל קו"ח - כמו במציאות.

### דרישות אותנטיות (זה עיקר המשימה)

- **מגוון ויזואלי אמיתי:** לפחות 6-8 תבניות עיצוב שונות מהותית - עמודה אחת/שתיים, עם/בלי
  צבע, פונטים שונים (serif/sans), עם/בלי תמונת placeholder של סקשן, שוליים שונים. קו"ח
  אמיתיים לא נראים אותו דבר.
- **מגוון איכות כתיבה:** חלק מלוטשים, חלק עם ניסוחים בינוניים, bullet ארוך מדי פה ושם,
  inconsistency קלה בפורמט תאריכים - כמו אצל אנשים אמיתיים. לא שגיאות בוטות בכולם.
- **ביוגרפיות קוהרנטיות:** רצף תעסוקתי הגיוני (תאריכים לא חופפים באופן מוזר, קידום סביר),
  חברות ישראליות/גלובליות מציאותיות-למראה **אבל לא חברות אמיתיות ספציפיות עם אנשים אמיתיים** -
  שמות אנשים, טלפונים ואימיילים בדויים לחלוטין.
- אורכים שונים: עמוד אחד ושני עמודים.

## שיטת עבודה מוצעת

1. לכתוב כל קו"ח כ-HTML (מספר תבניות CSS נפרדות) ולרנדר ל-PDF עם Playwright
  (`browser_navigate` ל-file:// + הדפסה ל-PDF, או סקריפט Node עם playwright שמותקן בפרויקט).
   חלופה: LibreOffice/pandoc אם זמין. העיקר - שהתוצר ייראה כמו קובץ שיצא מוורד/קנבה של מועמד.
2. לכל קובץ - רשומה ב-`manifest.json` (ראה מבנה למטה).
3. **שמות קבצים (הנחיית משתמש בעת האישור):** שם משמעותי שמקודד תפקיד/רמה/חוזק-תרחיש +
   שם אדם: `backend-senior-strong_Daniel-Peretz_CV.pdf`,
   `fullstack-mid-ambiguous_Noa-Levi_CV.pdf`. כך בוחרים קובץ נכון בשנייה בדמו ובתיוג.
4. **לא ATS-friendly בכוונה (הנחיית משתמש):** חלק ניכר מהקבצים בעיצובים "אמיתיים" שאינם
   נוחים לסריקה - שתי עמודות, sidebar, טבלאות - כל עוד יש שכבת טקסט ניתנת לחילוץ.

## מיקום התוצרים

```
test-fixtures/authentic-cvs/
  pdfs/<name>.pdf              (20-40 קבצים)
  src/<name>.html              (המקורות - לתחזוקה)
  manifest.json
```

מבנה רשומת manifest (עודכן ב-kickoff - מרחב אחד, בלי מיפוי כפול):
```json
{
  "file": "Daniel_Peretz_CV.pdf",
  "true_title": "Backend Developer",          // מתוך 59 הקנוניות (taxonomy.py), או "none"
  "acceptable_titles": ["Backend Developer", "Fullstack Engineer"], // לעמומים/היברידיים - למדידת Top-3 הוגנת
  "scenario": "clear-cut",                    // מהטבלה למעלה
  "seniority": "senior",
  "is_negative_fixture": false,               // true לעברית/סרוק - לא נספר במדדי דיוק
  "notes": "Django+Postgres+K8s; clean single-column layout"
}
```

**הרכב מאושר (kickoff 2026-07-14): 32 קבצים** - 29 אנגלית מתויגי-benchmark, 2 עברית
(עברית מלאה + מעורב; צפוי: דחייה מנומקת), 1 "סרוק" ללא שכבת טקסט (צפוי: הודעת שגיאה
ברורה). רינדור: `msedge --headless --print-to-pdf` (Edge קיים במחשב).
**אילוץ מהקוד:** זיהוי התפקיד קורא רק את 25 השורות הראשונות (`extractHeaderText`,
cv.service.ts) - שם+טייטל חייבים להופיע בראש הקובץ.
