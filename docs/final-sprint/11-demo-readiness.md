## מטרה

שביום השיפוט שום דבר לא מפתיע: המערכת קמה בפקודה אחת, יש תסריט דמו מלוטש, יש תשובה
מוכנה לכל שאלה צפויה, ויש תוכנית מגירה לכל תקלה. דרישה ישירה מפגישת המנחה
([12-meeting-summary-2026-07-05.md](../ds-models/12-meeting-summary-2026-07-05.md)):
בדיקות ידניות על קו"ח אמיתיים, פתיחת ה-CV בפועל לוודא שההמלצות נכונות,
**ומוכנות לבדיקות רנדומליות במהלך ההצגה**.

## חלק א' - סביבת דמו בפקודה אחת

- לבנות/לאמת סקריפט הרמה אחד (`scripts/demo-up.ps1` או docker compose profile) שמרים:
  Mongo (עם הדאטה), DS server (8000), backend (3000), frontend - ומוודא בריאות כולם
  (health checks, לא רק "עלה").
- לתעד ב-`docs/final-sprint/outputs/demo-runbook.md`: דרישות מכונה, פקודת הרמה, בדיקת
  בריאות, איך מאתחלים אם משהו נתקע, **ומה עושים בלי אינטרנט** (האם LLM calls חיוניים לדמו?
  אם כן - לתעד בדיוק אילו פיצ'רים דורשים רשת ומה ה-fallback).
- state נקי לדמו: משתמש דמו מוכן, היסטוריית ניתוחים מרשימה אבל לא עמוסה, בלי דאטת בדיקות
  מביכה ב-DB (לבדוק מה מופיע ב-Account וב-Admin!).

## חלק ב' - תסריט דמו (7-10 דקות + גרסת 3 דקות)

לבנות מסלול שמדגים את נקודות החוזק בסדר דרמטי נכון, עם קו"ח ספציפיים ממשימה 04 שנבחרו מראש:

1. פתיח: הבעיה (משפט אחד) → העלאת CV → **זיהוי תפקיד אוטומטי** (להשתמש בקו"ח clear-cut).
2. Personalization: הסבר קצר על Stable/Trending מדאטה אמיתי שנאסף לאורך זמן.
3. תוצאות: הציון, פירוק ל-10 סקילז, gap analysis.
4. Improve CV: שיפור section, שמירה, התוצאה המשולבת.
5. סיפור הדאטה: (אם מומש טאב האדמין) להראות שהמערכת לומדת יומית - וואו הנדסי לשופטים.
6. לכל צעד בתסריט: מה אומרים (משפט-שניים), על מה מקליקים, ומה אמור להופיע.

**מוכנות לבדיקה רנדומלית:** לתרגל עם 5-6 קו"ח מהסט של משימה 04 שלא הוצגו בתסריט,
כולל אחד עמום - ולתעד איך המערכת מגיבה (מסלול ה-manual selection הוא פיצ'ר, להציג אותו ככזה).

## חלק ג' - שאלות שופטים צפויות + תשובות

לבנות מסמך Q&A (עברית או אנגלית - לשאול את המשתמש באיזו שפה ההצגה). שאלות שחובה לכסות:

- "מה החדשנות? יש המון כלי CV" → התשובה מהאפיון: פותחים למועמד את מה שהיה סגור בצד המעסיק;
  שני מודלים + דאטה שנאסף לאורך זמן, לא wrapper ל-LLM.
- "המודל באמת לומד או שזה חיפוש דמיון?" → סיפור מודל 2: TF-IDF+LogReg, מניעת הדליפה,
  ההוכחה מול baseline (יש נרטיב מלא ב-[01-model2-cv-title-classifier.md](../ds-models/01-model2-cv-title-classifier.md)).
- "מה הדיוק האמיתי?" → המספרים ממשימה 05 - כולל הכנות לגבי ההבדל סינתטי/אמיתי (זה מרשים, לא מביך).
- "למה LLM לניקוד ולא מודל שאימנתם?" / "מה קורה כשה-LLM טועה?"
- "איך מתמודדים עם קו"ח בעברית?" (התשובה הכנה: English-only per scope באפיון).
- "מאיפה הדאטה? מותר לסקרפ את LinkedIn?" (להכין תשובה זהירה ומכובדת על שימוש אקדמי).
- "מה הייתם עושים אחרת?" → מחומר משימה 10.
- שאלות טכניות צפויות על ארכיטקטורה: למה Mongo, למה FastAPI נפרד, איך ה-promotion gate עובד.
