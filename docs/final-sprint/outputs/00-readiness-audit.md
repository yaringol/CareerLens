### B6. Frontend Developer → הסקיל הראשי הוא `backend` ✓ אומת ידנית
```
Frontend Developer: ['backend', 'react', 'typescript', 'javascript', ...]
Backend Developer:  ['python', 'microservice', 'software engineering', ...]
```
**שורש הבעיה:** `train.py` מחשב ושומר `title_specificity` (IDF), וה-README מתעד את הנוסחה
`0.7×prevalence + 0.3×title_match×title_specificity` — אבל קוד ההגשה
(`skill_schema.py:197-214`) ממיין לפי `prevalence` בלבד ואז לפי `stability_score`.
`title_specificity` **לא נקרא אף פעם**. הפיצ'ר שנועד למנוע בדיוק את זה מחושב ונזרק.

### B7. פיצ'ר ה-Trending מת — 0 rising, 0 falling ✓ אומת ידנית
כל 60,334 רשומות הסקילז מתויגות `stable`. הסיבה אריתמטית, לא כמות דאטה: הסף ל-rising הוא
יחס ≥1.25 ול-falling ≤0.80, בעוד שכל טווח היחסים בפועל הוא [0.84, 1.22] — **כולו בתוך
הרצועה הניטרלית**. `/title/trending-skills` לא יכול להחזיר טרנד לעולם.

### B8. ה-CV המשופר מיוצא כטקסט lowercase ללא פיסוק
`cv.service.ts:5-11` `normalizeCvText()` עושה lowercase, מוחק ירידות שורה ומסיר כל תו
שאינו `[a-z0-9]` — **וזה מה שנשמר ב-DB וזורם ל-Improve**. מכיוון שאין ירידות שורה,
`cvImprove.service.ts:107` (שמפצל sections על `\n\n`) מקבל את כל הקו"ח כ-section אחד.
התוצאה שהשופט רואה בסוף הדמו: פסקה אחת ארוכה, כולה אותיות קטנות, כתובת מייל שבורה —
מוצגת כ"קורות החיים המשופרים שלך".
