### שרשרת הזיהוי המלאה, עם הספים האמיתיים

```
POST /api/cv/title (cv.routes.ts:19) → detectTitleFromCv (dsModel.ts:109)
  → extractTitleFromCv → DS POST /cv/title (server.py:522)
       1. חילוץ מועמדי-כותרת מראש הקו"ח (_candidate_phrases)
       2. title_normalizer (embedding centroid) - מתקבל אם sim ≥ 0.55
          (TITLE_NORMALIZER_ACCEPT_SIM, server.py:123) וגם other_mass < 0.5 (veto)
       3. אחרת: המסווג הטקסטואלי (classify_cv_role_with_other_mass, :437)
          עם רה-נרמול confidence; low_confidence אם < 55 (:511)
  → חזרה ב-dsModel.ts: אם כל המועמדים < TITLE_LLM_FALLBACK_THRESHOLD (env, ברירת
    מחדל 55, :20) → classifyTitleWithLlm (רשימה סגורה, :141); ה-LLM מקבל confidence
    קבוע 70 (:25) ולעולם לא חוסם את הזרימה (:153-157)
  → UI: מתחת ל-AUTO_MATCH_CONFIDENCE_MIN=60 → הצעות/בחירה ידנית
```

### עובדות רלוונטיות לחיווט

- **ה-DS כבר מחזיק את כל מה שצריך בזיכרון**: `skill_extractor` (SkillNer, :390 בשימוש)
  ועכשיו גם `annotate_with_fallback` העמיד; טעינת artifact נוסף בעליית השרת היא
  תבנית קיימת (4 מודלים כבר נטענים כך).
- **עלות SkillNer על קו"ח: ~2.3 שניות** (נמדד ב-M06/M18) - תוספת לטנציה מורגשת
  אם רצה על כל upload.
- **מוקש unpickle ידוע**: ארטיפקט M18 נשמר עם `analyzer=identity` שהוגדרה במחברת -
  טעינה מחוץ למחברת דורשת את הפונקציה ב-scope. לפרודקשן חובה לשמור מחדש עם פונקציה
  מיובאת ממודול (`skillner_utils`) - אחרת השרת ייפול בעליית התהליך.
- **leakage guard חייב לחיות גם בהגשה**: המודל אומן על סקילז אחרי הסרת שמות-תפקיד;
  אותו סינון חייב לרוץ על הסקילז המחולצים ב-serve, אחרת ההתפלגות שונה מהאימון.
- כיסוי המודל: 24 מ-59 תפקידים; מחוץ לכיסוי הסיגנל חייב להיות ניטרלי.

## 3. הבעיה והפתרון

**הבעיה:** החלטת "מתי LLM" נשענת היום על confidence של מודל יחיד (סף 55). באזור
האפור המסווג טועה בשקט בביטחון בינוני - המקרים שבדיוק בהם M18 מדדה 40-60% דיוק
בלבד כשיש אי-הסכמה, מול 87% בהסכמה. הסיגנל קיים, מדוד - ולא מחובר.

**הפתרון:** מדרגת-הסכמה ב-`/cv/title`: כשהסולם מגיע לתשובה באזור האפור, מחלצים
סקילז (SkillNer שכבר בזיכרון) → המודל ההפוך → השוואה. הסכמה → boost שמונע LLM
מיותר; אי-הסכמה → הנמכת confidence שמפעילה את **פולבק ה-LLM הקיים** (אפס מדרגות
חדשות ב-backend). מתג env לכיבוי מיידי.

**חלופות שנדחו:** החלפת המסווג במודל ההפוך (M18 הראתה תיקו - אין הצדקה, והכיסוי
24/59); הרצה תמידית על כל upload (+2.3ש' גם כשהזיהוי ודאי - אין תמורה); חיווט
ב-backend (ה-DS מחזיק את ה-SkillNer והמודלים - שם המקום הטבעי).

## 4. תוכנית מימוש

1. **קיבוע הארטיפקט לפרודקשן**: תא קצר במחברת (או סקריפט חד-פעמי) ששומר מחדש את
   המודל עם `analyzer` מיובא מ-`skillner_utils` בשם יציב `ds/model/skills_to_title.joblib`;
   קומיט ב-LFS (התבנית הקיימת לארטיפקטי הגשה). אימות: `joblib.load` בתהליך נקי
   (בלי המחברת) + חיזוי על סט סקילז ידוע.
2. **מודול הסכמה ב-DS**: פונקציה טהורה `agreement_check(canonical, cv_text)` ב-server.py
   (או קובץ עזר): SkillNer עם fallback → leakage-guard (אותם 118 שמות) → multi-hot →
   predict; מחזירה `{skills_pred, agreement: agree|disagree|not_covered, skills_conf}`.
   טעינה בעליית השרת מאחורי `AGREEMENT_SIGNAL_ENABLED` (ברירת מחדל: כבוי עד אימות).
   אימות: unit test על שלושת הענפים + מקרה מודל-חסר (השרת עולה גם בלי הקובץ).
3. **שילוב בסולם** ב-`/cv/title`: הבדיקה רצה **תמיד** (הכרעת שאלה 1); הסכמה →
   `confidence = max(confidence, AGREEMENT_BOOST_CONFIDENCE=87)`; אי-הסכמה →
   כשהביטחון הבסיסי < `DISAGREEMENT_OVERRIDE_MAX=85`: `low_confidence=True` +
   הוספת חיזוי-הסקילז ל-candidates (מעל 85 - לוג בלבד, ראו ההחלטה הנגזרת);
   `not_covered` → ללא שינוי. שדות חדשים בתשובה: `agreement`, `skills_model_title`.
   אימות: קריאות API ישירות לשלושת התרחישים עם קו"ח אמיתיים מה-32.
4. **נגיעת backend מינימלית** (dsModel.ts): אין שינוי לוגיקה - ההנמכה/הגבהה כבר
   מגולמת ב-confidence שה-DS מחזיר, והמדרגה הקיימת (סף 55) עושה את השאר. שינוי
   יחיד: העברת `agreement` הלאה בלוג (`logTitleLlmFallbackUsed`) לניתוח עתידי.
   אימות: `npm run build` + בדיקת זרימה חיה.
5. **מדידה לפני/אחרי - ה-32 האותנטיים דרך ה-API החי**: אותו הרנס מ-M18, הפעם מול
   `/cv/title` המחווט (מופעל ב-env): כמה קו"ח שינו מסלול, כמה קריאות LLM נחסכו/נוספו,
   האם דיוק ה-top-1 עלה. התוצאות לדוח. אימות: הטבלה המלאה פר-קו"ח.
6. **Playwright**: העלאת קו"ח Data Scientist (צפוי: agree, בלי LLM) + קו"ח עמום
   (datasci-ml - צפוי disagree→LLM/הצעות) + קו"ח האחות (uncertain נשאר מוגן). צילומים.
7. **דוח** `outputs/19-agreement-wiring-report.md` + עדכון קיקוף/תוכנית-על/דף.

**עצירה בטוחה:** אחרי כל צעד; המתג כבוי עד צעד 5 - הפרודקשן לא משתנה עד שהמדידה עברה.
**Out of scope:** UI (חיווי הסכמה ויזואלי) · שינוי ספים קיימים (55/60) · הרחבת כיסוי
המודל · ה-preset של הסליידר (ממצא M06).
