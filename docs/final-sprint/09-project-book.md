2. **שקיפות על תהליך המחקר** - כולל הניסויים שנכשלו והלקחים (החומר ממשימה 10).

- **System Design & Implementation:** **צורך את `docs/architecture.md` ואת שלוש הדיאגרמות

  אגנטי ה-LLM, מסכי המערכת.

- **Results & Analysis:** **מקור יחיד: `outputs/official-metrics.md` (משימה 05).**
  ⚠️ **אסור לצטט: 0.93 / 0.932 / 0.981** — הם נמדדו על דאטה סינתטי, והמדידה החדשה של
  הצוות עצמו (`ds/model/TITLE_DETECTION_METHODOLOGY.md`) סותרת אותם (62.3% / 0.732).
  להציג מספר שהמנחה יכול להפריך מתוך הריפו שלכם = איבוד אמינות מיידי.
  **אסור לצטט גם "15/15 passed"** מ-`poc_files/RESULTS.md` — ה-harness מנסה עד 3 פעמים עד
  שהציון נופל ברצועה שהצוות עצמו הגדיר. זה מעגלי.
  ה-ablation של הדליפה (leakage) **כן** ראוי לדיווח — אבל כ**סיפור מתודולוגי** (§4.3/§4.5:
  "כך גילינו דליפה וכך תיקנו אותה"), לא כמדד ביצועים של המערכת שהוגשה.
- **תהליך וניסוי-וטעייה:** `outputs/trial-and-error-chronicle.md` ממשימה 10.

## סעיף "תוכנן מול בוצע" (דרישה מפורשת של המשתמש)

לבנות טבלה/פרק השוואה שיטתי מול האפיון. סטיות שכבר ידועות (לאמת מול הקוד ולהעמיק):

| באפיון | בפועל | כיוון ההסבר |
|---|---|---|
| "Python AI service" יחיד מאחורי backend | פיצול: FastAPI DS server (2 מודלים) + אגנטי LLM בתוך ה-Node backend | הפרדת אחריות: מודלים סטטיסטיים מול קריאות LLM; האפיון לא צפה שני סוגי "אינטליגנציה" שונים |
| סקרייפינג Glassdoor/AllJobs עם Selenium | LinkedIn scraping + dataset חיצוני (lang-uk) + pipeline יומי עם promotion gate | האפיון לא צפה rate-limiting/חסימות, ולא את הצורך בהיסטוריה לאורך זמן לטרנדים |
| 5 Core = טכני, 5 Dynamic = רך | Core מהמודל הסטטיסטי per-title; Dynamic מחילוץ מה-JD (LLM/SkillNer) | ההגדרה המקורית hard/soft התבררה כלא-אופרטיבית; החלוקה האמיתית: "מה התפקיד דורש בשוק" מול "מה המשרה הספציפית מבקשת" |
| משתמש בוחר תפקיד מ-dropdown | זיהוי תפקיד אוטומטי מה-CV (מודל 2) | פישוט UX + אתגר ML מעניין יותר. **תוקן:** URL scraping **לא** הוסר - הוא עובד (`jobPostingFetcher.service.ts`, נבדק חי מול LinkedIn). הגרסה הקודמת של שורה זו הייתה שגויה |
| **"Gap Analysis: comparison table"** + מסך Skill Deep-Dive (mockup `image3.png`) + "semantic feedback" מסוכן הניקוד | ⚠️ **תלוי בהחלטת משימה 15** - נכון לביקורת, לא מומש כלל (הסוכן מחזיר רק `{skill, score}`) | אם נחתך: להסביר **למה**, ולהעביר ל-Future Work. **זו שורה שהמנחה יחפש** - היא דרישה פונקציונלית מפורשת עם mockup מלא |
| **"weighted average" Global Match Score** | ממוצע **לא-משוקלל** (`calcMatchScore` = sum/length) | סטייה קטנה אך מפורשת. או לממש שקלול core/dynamic, או **לא לחזור על המילה "weighted"** בספר ולהסביר את הבחירה |
| **ייצוא: "download the improved content"** (mockup: Download PDF, before/after) | ייצוא `.txt` בלבד | לתעד. (איכות התוכן עצמו - ראה משימה 14 P0-2) |
| API מתוכנן (`/cv/upload`, `/analysis/score`...) | ה-API בפועל (`/api/upload`, `/api/analyze`, `/api/personalize/...`) | אבולוציה טבעית; למפות endpoint-מול-endpoint בנספח. **גם: 5 endpoints מוגדרים אך לא נקראים מה-UI** - להחליט: למחוק או לתעד |
| Work plan של 9 שבועות ל-4 אנשים | ציר הזמן האמיתי: 2026-01-11 עד 2026-07 = **~25 שבועות** | לספר בכנות איפה ההערכות היו אופטימיות. הסקופ **גדל**: מסווג טייטלים, Personalization, Improve-CV, השוואת קו"ח, פייפליין יומי - אף אחד מהם לא היה באפיון. זה ממצא לגיטימי, לא כישלון |

לכל שורה: לא רק "מה השתנה" אלא **מה הפספוס באפיון** - זו הדרישה של המשתמש.
**חובה לאמת כל שורה מול הקוד לפני כתיבה** (השורה על URL scraping הייתה שגויה בדיוק כך),
ולחפש סטיות נוספות שלא ברשימה.
